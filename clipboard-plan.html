A clipboard that feels native to this machine

Build a private, keyboard-first clipboard history for Ubuntu GNOME on Wayland: fast enough to summon, search, and reuse copied text without interrupting the current task.

What the machine tells us

DesktopUbuntu GNOME 46
Display sessionWayland, with XWayland available
Current toolingNode 24 and Python 3.12; no Rust, Electron, or clipboard CLI
Existing managerNone detected
The consequential constraint: Wayland intentionally limits background clipboard access. On GNOME, Shell-level integration is the cleanest path for continuous capture; a generic desktop or web app is a weaker foundation for a clipboard manager.

Recommended product shape

Trial a trusted existing GNOME option before building.

Clipboard Indicator already covers the core workflow on this machine and can open history from a global shortcut. Trial it with Super+V; build only if a Windows-style floating flyout, rather than a top-bar-anchored popup, is a meaningful requirement.

If a custom build is still justified, keep the original direction: a GNOME Shell extension that is local-only, keyboard-first, and text-first.

The Windows-style interaction contract

  1. Press Super+V from any normal application.
  2. A compact clipboard-history popup appears without switching applications.
  3. The newest item is selected; typing filters the history immediately.
  4. Use arrow keys to move, Enter to restore the selected item, and Escape or an outside click to dismiss.
  5. The previous application keeps its context. The default action copies the item back; optional direct paste is a separate, explicit behavior.
Shortcut ownership on this machine: GNOME currently binds Super+V and Super+M to the message tray. To match Windows, remove only Super+V from that GNOME action, retain Super+M for notifications, and assign Super+V to clipboard history.

Already-built options worth considering

Clipboard Indicator
GNOME Extensions		 About 2.43M downloads, 1.2K GitHub stars, active GNOME 46 release, and updates in May 2026. Includes search, images, pins, tags, app exclusions, private mode, and automatic clearing. The exact GNOME 46 package was inspected: no network client or subprocess behavior was found. It provides the shortcut-to-popup behavior, but the popup drops from the top bar. Disable image caching initially because large images have a documented Shell-freeze risk.

Clipboard History
GNOME Extensions		 About 583K downloads, 600+ GitHub stars, active GNOME 46 release, search, private mode, and favorites-only persistence. The exact GNOME 46 package showed no network client or subprocess behavior. Its append-only local store is performance-conscious, but still holds clipboard data unencrypted. Good, but second choice. The maintainer says it is in maintenance mode while being replaced by Ringboard.
CopyQ / Diodon / Parcellite All are available from Ubuntu, but they are generic desktop managers rather than the strongest GNOME Shell path for this Wayland session. Popularity or repository packaging does not remove Wayland integration limitations. Skip for this machine.
What “safe” can mean here: no clipboard manager is harmless by design—it must read copied passwords, tokens, messages, and other sensitive text. GNOME Shell extensions also run inside the desktop Shell rather than a strict sandbox. Prefer the official GNOME Extensions or Ubuntu repository package, keep history short, enable application exclusions/private mode, and clear history regularly.

Not recommended: Pano has a more visual flyout but still has an unresolved GNOME 46 support gap; the extension named “Clipboard Popup” explicitly targets the Windows interaction but remains unapproved and has negligible adoption. Neither meets the current “safe and popular on this machine” bar.

Three viable directions

Direction Best part Cost / limitation Fit here
GNOME Shell extension Native background clipboard access and low-friction panel UI on Wayland. Tied to GNOME APIs; Shell upgrades sometimes require compatibility work. Recommended
Extension + companion app Richer window, database, image previews, and stronger separation of concerns. More moving parts, packaging, IPC, and failure modes before the core workflow is proven. Phase 2 option
Standalone GTK app Portable application architecture and familiar app window. Background clipboard monitoring on GNOME Wayland is the hard part; may still need a Shell bridge. Not first

The first useful version

  • Capture changed plain text, deduplicate consecutive copies, and move reused items to the top.
  • Open a compact searchable history from a global shortcut, tentatively Super+V.
  • Select with keyboard or pointer; selection restores the item to the clipboard.
  • Pin important snippets, delete individual items, and clear all unpinned history.
  • Keep a bounded local history—tentatively 200 items—and survive logout/restart.
  • Exclude empty values, very large payloads, and likely secrets when a conservative rule can identify them.
Explicitly outside the first version: cross-device sync, accounts, collaboration, OCR, clipboard transformations, rich HTML, file lists, and image history. These can be revisited after the text workflow proves itself.

Decision and delivery checkpoints

01 · TRIAL

Use Clipboard Indicator

Install from the official GNOME Extensions directory. Disable image caching, set a short history, enable password-manager exclusions, and use private mode deliberately.

Pass: the existing tool is stable and covers the daily workflow without an unacceptable privacy or UX gap.

02 · DECIDE

Keep, switch, or build

Record only concrete misses: performance, keyboard flow, secret handling, visual design, or reliability. If packaging trust is the concern, trial GPaste next.

Pass: a custom build proceeds only with a crisp advantage existing tools cannot provide.

03 · BUILD IF JUSTIFIED

Prove the differentiator

Start with clipboard access and the one workflow that creates the advantage, then add persistence and privacy safeguards.

Pass: the custom version is measurably better at the reason we chose to build it.

Decisions for our discussion

What should “clipboard” mean?

A history manager, a reusable snippet library, or both?

Working default: history first, pins provide lightweight snippets.

Copy or paste?

Should choosing an item only put it on the clipboard, or also paste into the active app?

Working default: copy only; auto-paste can be surprising and fragile.

What content matters?

Plain text only, or are screenshots/images and copied files essential from day one?

Working default: text first; assess images after the access spike.

How private should persistence be?

Session-only, retained across restarts, or encrypted at rest?

Working default: persisted locally with conservative exclusions and a one-action clear.

What is the primary surface?

Is shortcut-to-popup enough, or must placement and styling closely mirror the Windows floating flyout?

Working default: trial the top-bar popup first; a true floating flyout is the clearest possible reason to custom-build.

Personal tool or distributable product?

Supporting only this machine is simpler than packaging for arbitrary GNOME versions.

Working default: personal tool for GNOME 46, with clean seams for later packaging.

Privacy and failure boundaries

  • Pause capture while the screen is locked and never expose history on the lock screen.
  • Offer an obvious pause state for password managers, private work, or screen sharing.
  • Treat secret detection as defense in depth, not a guarantee; clipboard contents can be inherently sensitive.
  • Store only what the product promises, bound both item count and item size, and make deletion immediate.
  • Clean up Shell signals and timers on disable so extension reloads do not leak resources or duplicate entries.

Research anchors

Machine facts and Ubuntu package candidates were inspected locally. Exact GNOME 46 distribution archives for the two leading extensions were downloaded and statically checked for obvious network and process-launch behavior. Adoption, compatibility, status, and features were cross-checked against Clipboard Indicator, Clipboard History, their linked source repositories, the Ubuntu GPaste package record, the official GNOME Shell extension UI guide, and the GNOME 46 porting notes.
