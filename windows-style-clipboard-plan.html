Behavior plan · 28 July 2026

A Windows-style clipboard popup, native to this GNOME desktop

Press Super+V anywhere to reveal a fast, searchable clipboard flyout over the current app; choose an item from the keyboard and paste it without breaking focus.

Concept direction

The four-second workflow

01 · OPEN

Super+V

The flyout appears over the active app without entering Activities or opening another window.

02 · FIND

Type or navigate

Typing filters instantly. Arrow keys move through recent and pinned items.

03 · PASTE

Enter

The selected content is restored and pasted into the app that was active before the flyout.

04 · RETURN

Popup closes

Focus returns to the original app. The selected item becomes most recent.

Intended behavior

Moment What the user experiences
When content is copied Text and images enter history in the background. Consecutive duplicates collapse into one item; an older duplicate moves to the top instead of creating another copy.
When opened The popup appears on the monitor containing the focused window, centered slightly above the midpoint. The desktop behind it dims subtly, the newest item is selected, and search is ready immediately.
While searching Normal typing filters text items by content. Search never modifies the stored history. Clearing the query returns to the full list with pins first and recent items below.
When navigating ↑/↓ move one item, Page Up/Page Down move a viewport, and Home/End jump to the first or last result. Pointer and touch remain supported.
When choosing an item Enter makes the item current, closes the popup, restores focus, and attempts an immediate paste—the Windows-like default. Shift+Enter copies without auto-pasting.
If direct paste is unsafe For an unsupported app or protected field, the item is still copied, focus returns, and a small notice says “Copied — press Ctrl+V”. Content is never sent to the wrong window merely to preserve auto-paste.
When dismissed Escape, Super+V again, clicking outside, changing workspace, or locking the screen closes the popup without changing the clipboard.
After restart Pinned items and the allowed recent history return. The last copied item is not automatically pasted or exposed on screen.

Popup anatomy

Header and search

Clipboard title, one privacy/pause control, and a single search field. No settings maze inside the frequent-use path.

History cards

Preview, relative age, pin state, and a quiet overflow action. Long text is clamped; selecting a card can reveal more without resizing the whole popup.

Selection

A strong indigo outline and surface change identify the keyboard target. Selection never depends on hover alone.

Footer hints

Only the essential commands remain visible: navigate, paste, and close. Secondary actions appear contextually or through keyboard help.

Responsive bounds: target width is approximately 440 px. Height grows to about five items, then the list scrolls. On small displays the popup keeps a safe edge margin; on multiple monitors it follows the active window.

Keyboard contract

Shortcut Action Notes
Super+V Open or close clipboard GNOME notifications keep their existing alternative, Super+M.
Enter Paste selected item Returns focus and closes on success or safe copy-only fallback.
Shift+Enter Copy without paste Useful for terminals, remote desktops, and protected fields.
Ctrl+P Pin or unpin Pinned entries persist until explicitly deleted.
Delete Delete selected item Removal is immediate; selection moves to the next item.
Ctrl+Shift+Delete Clear unpinned history Requires a confirmation surface because it is destructive.
Escape Close without action Leaves clipboard and history unchanged.

Privacy is visible, not buried

Everything stays on this machine.

No account, sync, analytics, network calls, or cloud processing. Stored content is local and bounded by both item count and payload size.

  • Pause capture from the popup header; paused state is visually unmistakable.
  • Never capture or display history while the session is locked.
  • Allow application exclusions, starting with detected password managers.
  • Default to a bounded history of 200 entries; pinned items are managed separately.
  • Offer session-only history, persistent history, clear-on-lock, and clear-on-logout policies.
  • Do not claim secret detection is perfect. Users can always pause, exclude, or clear.

Scope for the first release

Included

  • GNOME 46 on this Ubuntu Wayland machine
  • Plain text and common copied images
  • Search, keyboard navigation, pin, delete, and clear
  • Persistent or session-only local history
  • Direct-paste attempt with copy-only fallback
  • Light/dark theme adaptation and multi-monitor placement

Deferred

  • Cloud or cross-device synchronization
  • Copied files and rich HTML fidelity
  • OCR, transformations, templates, and AI actions
  • Support for non-GNOME desktops
  • Public extension-store packaging
Performance boundary: image decoding, thumbnailing, and persistence must not block GNOME Shell. If images cannot meet the responsiveness target safely, text ships first and image history remains behind an experimental setting.

Build checkpoints

  1. Interaction prototype: Super+V opens and dismisses a focus-safe popup on the active monitor; keyboard navigation feels immediate.
  2. Clipboard core: capture and restore text reliably across native Wayland and XWayland applications; deduplication and ordering stay correct.
  3. Windows-like paste: direct paste works in common GTK, Chromium, Electron, and terminal applications, with an honest copy-only fallback.
  4. Trust layer: bounded persistence, pins, pause, app exclusions, lock handling, deletion, and restart recovery behave predictably.
  5. Image gate: thumbnails are asynchronous and copying large images does not freeze or destabilize the Shell.

Acceptance checks

  • Popup appears within 150 ms of Super+V with a warm history.
  • Search visibly responds within one frame for 200 text items.
  • The user can reuse the third-most-recent item without touching the pointer.
  • Escape always restores the previous app without changing clipboard state.
  • A failed auto-paste never inserts content into a different window.
  • Nothing is captured or shown on the lock screen.
  • Disabling the extension removes shortcuts, signals, timers, and popup actors cleanly.
  • A corrupted cache cannot prevent GNOME Shell from starting or the extension from disabling.

Working assumptions

This is a personal GNOME 46 tool first. “Windows-style” means the rapid Super+V flyout workflow and direct reuse of an item, while the visual treatment adapts to GNOME rather than copying Microsoft assets pixel-for-pixel. The generated concept is directional; accessibility, theme integration, and Shell performance take priority over exact visual fidelity.
